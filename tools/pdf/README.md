# Unified PDF review and print preparation

Public entry: `portal/herramientas.html`, linked from the portal before login and under Herramientas. Tool: `tools/pdf/index.html`. Runs on the visitor's device without authentication, storage or file uploads. Pinned external PDF-LIB 1.17.1 and PDF.js 6.4.299 provide generation and preview; external assets need network access. No Adobe credentials or integration is present.

The same window inspects page count, page boxes, rotation and mixed cut sizes; offers cut marks, user-selected white/uniform-color bleed completion, Arabic-numeral page numbering and two-up saddle-stitch imposition in RTL (default) or LTR. Copies vector content without rasterizing. Original exterior space and marks are preserved by default; explicitly reconstructing marks, changing trim or imposing rebuilds the exterior. The server-only Adobe adapter is prepared in `supabase/functions/_shared/adobe-bleed.mjs`; it is NOT deployed or enabled and has no public endpoint. Live Firefly Services credentials/entitlement are missing. No paid Adobe request has been made. The core can composite a returned PNG/JPEG into four clipped outer strips without changing the original page. Authentication, metering, a live Adobe test and browser upload/return wiring must be completed before exposing this feature. The tool recognizes a complete eight-arm vector crop-mark pattern aligned to the cut, reports partial patterns separately, and never treats failure to identify marks as proof of absence. It does not infer page numbers or real ink coverage from PDF boxes and does not certify fonts, color or resolution. Source annotations/links are not reproduced in the print copy. Interactive forms/signatures and encrypted PDFs are blocked; rotated source pages require a fresh export. Limits: 200 MiB and 400 pages.

TrimBox is preferred; absent it, CropBox is the cut reference. A custom final size is centered in the CropBox. Bleed availability is constrained by MediaBox and explicit BleedBox, falling back to CropBox when there is no BleedBox. Never assume space outside CropBox is artwork. Specifying insufficient bleed without choosing a fill fails explicitly. Uniform fills paint outside the cut only and require the user to verify that the selected color matches the background. Pages are never scaled to invent bleed.

Saddle-stitch output uses one signature, padded at the end to a multiple of four; each sheet alternates front/back. No creep, printer registration adjustments or multiple-signature/perfect-binding layout. At the spine, bleed is clipped to avoid overlap; outer edges retain it. Marks refer to the combined cut of the spread and sit beyond the bleed. Required paper dimensions are reported; print at 100% on a suitable sheet. Output must be previewed and acknowledged before downloading; changes invalidate any previous result and revoke its URL.

Validation: `node tests/pdf-print.cjs` writes temporary numbered/color fixtures and prints their directory. Run `python3 tests/pdf-print-render.py <directory>` to independently verify PDF rendering, left/right placement, numbering and bleed geometry using PyMuPDF. `node tests/pdf-print-ui.cjs` runs the full UI flow with real PDF generation and a stub only for external preview rendering. Browser rendering/CDN behavior still needs an end-to-end browser check.


Fold guides: choose two, three or four panels on the open artwork. Equal-panel accordion folds are calculated from the final open width. Three-panel roll fold supports a narrower left/right entry panel; other folds can supply explicit positions. Marks appear outside top/bottom and are dashed to distinguish them from cut marks. Reverse-side positions are reflected by default and can be disabled. Single-page PDFs hide/disable booklet imposition; the core also rejects it.
